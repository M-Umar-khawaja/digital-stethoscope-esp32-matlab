Stethoscope Software Design

The MATLAB R2024b software from the USB cable onwards: live display, 20-second recording, S1/S2 detection, heart rate, intervals, signal quality and a normal/abnormal screening result trained on 6130 recordings from PhysioNet/CinC 2016 and CirCor 2022, with simulated-sensor copies so the model ignores the microphone. No MATLAB toolboxes are needed. Everything below was checked in GNU Octave 9.4; the dashboard window itself still has to be opened once in MATLAB.

Processing chain

acquire

ESP32 ADC counts, 4 kHz → parser → ring buffer. Live path: causal notch + 20–500 Hz filter, chunk by chunk, every 2nd sample kept.

pre-process

Resample to 2 kHz (same as PhysioNet) → notches at 50–250 Hz (Q 35) → zero-phase 4th-order Butterworth 25–400 Hz → spike removal → unit variance.

heart rate

Autocorrelation of the homomorphic envelope, lag 0.4–2 s (30–150 bpm), with a check against locking onto half the beat.

segment

4 envelope features at 50 Hz → logistic-regression emissions trained on 270 hand-corrected recordings → extended Viterbi with Gaussian state durations. Output: S1, systole, S2, diastole for every sample.

quality

Clipping, too few cycles, implausible heart rate, then a 5-feature logistic quality score. Poor recordings get a reason and a retry, never a diagnosis.

classify

124 features (Potes 2016, challenge winner): durations and ratios, amplitude ratios, skewness and kurtosis, 9 band powers and 13 MFCCs per state → standardise → RBF SVM (C = 1, γ = 1/124) → probability.

Design decisions

Changed or added to the proposal

  • 50 Hz notch added. Mains hum in Pakistan sits inside 20–500 Hz, so a band-pass alone cannot remove it.
  • Two bands. 20–500 Hz keeps the proposal's band for display and listening; 25–400 Hz matches the method the model was trained with.
  • HSMM instead of plain peak picking. Envelope peaks alone confuse S1 with S2; the duration model uses the fact that systole is shorter than diastole.
  • Quality gate added. Commercial analysers (Eko) check quality first; a noisy clip says "retry".
  • Live view + 20 s analysis. Classification needs many beats and zero-phase filtering, which work on a finished clip.

Engineering choices

  • No toolboxes. Butterworth design, filtfilt, Hilbert, spectrogram, logistic regression and SVM are written in plain MATLAB, so the app runs on any R2021a+ install.
  • Patient-grouped testing. All recordings of one patient stay in one fold, so scores are not inflated.
  • Validation folder unused. PhysioNet's "validation" files are copies of training files.
  • Same code live and offline. The dashboard calls the same functions the tests check.
  • Simulated device. Streams a PhysioNet recording in the ESP32's exact format, for testing without hardware.

Limits to state in the viva

Device accuracy is preliminary

On public recordings the classifier scores 84.0%. Through the real ESP32 + MAX4466 sensor, heart sounds look more "abnormal" (public model: 67% on device copies vs 83% on the originals). Calibration used 30 public recordings played through an earbud onto the diaphragm (checked to really carry the heartbeats) and 12 recordings of one healthy heart at 4 positions. With a device threshold of 0.80, held-out device clips score 65.5% (Se 47%, Sp 84%). More real patient recordings with the sensor are the main future work.

Device signal quality

  • The PhysioNet-trained quality model could not separate good device clips from noise, so ESP32 input uses rule checks plus a spikiness test (log kurtosis ≥ 1.25: white noise 1.1, chest recordings ≥ 1.5).
  • Handling the chest piece and breathing cause most rejected clips; the dashboard's LEVEL meter helps set the gain before recording.
